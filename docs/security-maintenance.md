# 安全边界与依赖维护

## 订阅链接与后台登录

Shadowrocket 等客户端通过完整分享链接获取订阅，不需要后台登录 Cookie。`isPublic` 控制是否在公开列表展示，不改变持有分享链接的客户端读取权限。分享链接不是后台管理员会话，不能用于调用管理 API。

应将“持有分享链接可读取”和“未持有链接的人能否猜到链接”分开评估。公开配置可能包含分享路径前缀，因此不应仅依赖此前缀隐藏订阅；需要保密的链接应使用不可猜测的路径组件，短自定义 ID 属于容易传播、容易猜测的分享地址。调整凭据或链接格式前，需要评估现有客户端链接的兼容性。

## 管理操作的方法约束

以下操作只能通过 `POST` 调用，且保留后台认证与现有 CSRF 校验：

- `/api/migrate_to_d1`
- `/api/migrate_legacy_d1`
- `/api/migrate`
- `/api/cron/trigger`
- `/api/settings/sessions/revoke`

其它方法在操作和存储访问前返回 `405 Method Not Allowed`，并设置 `Allow: POST`。带有效 Cookie 的跨站 `POST` 仍返回 `403`。GET/HEAD 导航不会触发迁移或手动同步。

## 订阅参数与缓存

分享链接继续免登录使用。请求中的 `rename=old@new|A@B` 仅进行大小写敏感的普通字符串替换，不再执行调用者提供的任意正则；`include` / `exclude` 对节点名称进行大小写不敏感的普通文本匹配，支持 `|` 分隔。每个参数最多 1024 字符、最多 16 条规则，变更后的节点名称最多 1024 字符。管理员已保存的算子配置不属于此请求参数接口。

共享缓存只保存管理员配置生成的基础结果，请求级改名、筛选和国旗选项在缓存之后单独处理。聚合缓存使用 v2 键，忽略旧版本可能被参数污染的缓存；请求变体不会创建无限的新缓存条目。

## 后台会话与登录失败限制

新版后台 Cookie 使用 Web Crypto HMAC，绑定管理员密码、Cookie 密钥和持久化会话版本。`COOKIE_SECRET` 环境变量优先于旧 KV 值，因此轮换环境密钥可使旧 Cookie 失效。原生 Node 启动时记录凭据的 HMAC 指纹，在凭据变化时更新会话版本；保持凭据的普通重启保留新版会话。修改 KV 管理员密码或使用安全设置中的“退出所有设备”也会撤销旧登录。30 天会话时长与 7 天活跃续期规则保持不变；本次升级前的旧版 Cookie 需要重新登录。订阅链接不受会话撤销影响。

`POST /api/settings/sessions/revoke` 需要管理员登录与 CSRF 来源校验，成功后撤销所有后台会话并清除当前 Cookie。原生 Docker 的管理员密码由 `service.env` 管理，修改后需重建容器；不能通过页面覆盖此环境变量。

登录接口在应用内按可信来源 IP 计数：15 分钟内 5 次失败后，下一次请求返回 `429` 和 `Retry-After`，首次等待 30 秒，继续失败按倍数增加，最长 15 分钟。成功登录清除该来源的失败计数。计数采用有容量和过期限制的进程内存，不持久化密码，不把一个来源的失败变成全账号锁定。原生 Node 单进程内立即生效，重启会重置计数；多实例或 Cloudflare 部署需要独立的共享限流方案。

不修改 Nginx，不新增 Nginx 限流。Compose 中 `MISUB_TRUST_PROXY=true` 仅用于当前本机代理部署：只有连接来自回环地址或容器默认网关时，才读取现有 Nginx 已覆盖的 `X-Real-IP`；仅当该值属于 Cloudflare 官方网段时才接受 `CF-Connecting-IP`。不使用客户端提供的 `X-Forwarded-For` 首项。未启用此选项、来自其它容器的直连、缺少或无效的来源头均退回连接 IP。开放容器端口给公网或更换代理时，应先关闭该选项并重新核实信任边界。

每个来源最多同时进行 5 个登录尝试，避免并发请求在密码检查完成前穿过失败阈值。登录成功、失败和限流事件写入不含密码/Cookie 的审计日志，每进程每分钟最多记录 20 条；Docker 日志轮转为每份 10 MiB、保留 3 份。

## 原生 Node 外部拉取

原生部署使用 [Undici](https://github.com/nodejs/undici) 处理 HTTP、TLS 和解压。订阅、预览、远程模板、同步等拉取共用受限下载入口：禁止私有/本机地址，连接时校验 DNS 返回的地址并把已验证地址直接交给连接器，最多跟随 3 次且逐跳检查的重定向，跨源跳转移除认证等敏感请求头，禁止 HTTPS 降级。

原生外部下载全局最多 4 个并发，每次下载最多 8 MiB（含解压后大小），并为 DNS/连接/响应体设置完整超时和取消；原生传输上限 10 秒，连接上限 5 秒。代理和 HTTP(S) 来源也受此规则约束，不能用于访问 VPS 内网服务。来源超时或被拒绝时，已有的保护性节点缓存仍按原规则回退。手动节点导出不需要外部拉取。

## 依赖维护

生产镜像只包含编译后的前端、后端及 Node.js 原生适配层，不复制 `node_modules`。前端安全库和打包进后端的依赖仍需及时更新；开发依赖不在生产镜像中，也应修补其构建、测试和开发服务器风险。

本轮更新的安全基线：

| 依赖      | 版本基线 | 使用范围                   |
| --------- | -------- | -------------------------- |
| DOMPurify | 3.4.17   | 前端公告与自定义 HTML 清理 |
| js-yaml   | 4.3.2    | YAML 解析和输出            |
| Vue       | 3.5.45   | 前端运行时及构建工具链     |
| Vite      | 7.3.8    | 开发和构建                 |
| Vitest    | 4.1.12   | 测试                       |
| Happy DOM | 21.0.4   | 测试环境                   |
| esbuild   | 0.28.2   | Node.js 后端打包           |
| Undici    | 8.12.4   | 原生部署外部 HTTP/TLS 拉取 |

保留 Vue Test Utils 的 2.4 系列，通过 `package.json` 的定向 `overrides` 将 `js-beautify` 使用的 `glob` 升至 14.0.4 及以上，将其 `editorconfig` 使用的 `minimatch` 升至 11.0.5 及以上。这两个包仅属于测试格式化依赖链；更新或移除覆盖配置时，需重新验证 Vue 组件测试、格式化和 EditorConfig 行为，避免引回已公告的拒绝服务问题。

Playwright 没有仓库内调用，已从开发依赖移除。DOMPurify、js-yaml、二维码、拖拽和压缩相关依赖存在实际调用，继续保留。

HTML 净化组件测试单独使用 jsdom 31；其它组件测试继续使用 Happy DOM。[DOMPurify 官方说明](https://github.com/cure53/DOMPurify#running-dompurify-on-the-server)不推荐与 Happy DOM 组合使用，因此净化测试需使用其推荐的 jsdom 环境，保留脚本与危险属性的拦截断言。jsdom 31 要求 Node.js 22.22.2+（22 系列），本项目 CI 和 Docker 使用 Node.js 22。

更新锁文件后检查：

```sh
npm ci --no-audit --no-fund
npm audit
npm run test:run
npm run test:node
npm run build
```

`npm audit` 的依赖告警不等于线上接口已经可被利用；还需结合代码调用、配置和部署方式评估。扫描结果只覆盖其数据库收录的已知问题，不构成无漏洞保证。
